# 品質ゲート基準

**★の項目は `gate_check.mjs` が自動判定する**（基準値は `studio/gates.json`）。エージェントが見るのは★の無い項目だけ。

数値は目安。ゲームの性質上当てはまらない項目は、PM が `studio/decisions.md` に理由を書いて置き換える（勝手に無視しない）。

## スライス基準（Phase 3 — 面白さの核）

垂直スライスは「コアループだけで面白いか」を判定する。ここで FAIL なら飾りを足しても直らない。

| 項目 | 基準 |
|---|---|
| ★初回の意味ある操作 | 起動から10秒以内（説明を読まずに） |
| ★1ランの長さ | 狙いの範囲内（concept.md に記載、例: 30〜120秒） |
| ★失敗→次のラン開始 | 2タップ以内・3秒以内 |
| ★上達の余地 | 上達者ボットの中央値スコアが初心者ボットの1.5倍以上（運ゲーでない） |
| ★初心者の到達 | 初心者ボットでも半数以上が「最初の小さな達成」に届く（突き放しすぎない） |
| 新規性の一点 | concept.md の「新規性の一点」がスライス内で体験できる（スライスでは playtester、リリースでは reviewer が判定） |
| 手応え | 主要な操作に視覚＋（あれば）音の反応がある、入力遅延を感じない |
| ★安定 | 短時間プレイ（既定 3ラン×40秒）でコンソールエラー0 |

## リリース基準（Phase 5）

スライス基準すべて ＋ 以下。

**体験**
- 最初の5分で新しい要素・目標が少なくとも3回出てくる（中だるみしない）
- ★詰まり地点がない: 同じ地点での失敗が全失敗の40%を超えない（意図したボス等は除く、balance.md に記載）
- 何らかの積み上げ（記録、アンロック、図鑑、ベストスコア）がある
- 一時停止、ミュート、設定、遊び方の再表示ができる

**技術**
- ★`npm test` と `check_build.mjs` が通る
- 390×844 と 360×640 と 430×932 で表示崩れがない（スクショ。eco では reviewer が確認）
- 60秒放置・バックグラウンド復帰・画面回転で壊れない
- 保存データが壊れていても起動する
- オフラインで起動する（サービスワーカー）
- ★平均30fps以上（ヘッドレス計測なので参考値。極端な低下がないこと）

**一貫性**
- 直近の world-audit と design-audit のブロッカーが0
- `game/README.md` に遊び方とクレジット

**権利**
- gs-legal のリリース判定が GREEN か、YELLOW の対応済み
