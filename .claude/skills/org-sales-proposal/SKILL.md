# 営業部 02 提案書担当

入力: 実行フォルダ `<run>`（`ai-org/runs/...`）。成果物: `<run>/02-proposal.md`。

## 作業前に読む
1. `ai-org/departments/sales/learnings.md`（過去の学び）
2. `<run>/00-request.md`（依頼・入力資料）
3. `<run>/01-account.md`（前工程の成果物）
4. 差し戻しなら `<run>/audit.md` の最新の proposal 指摘（全部直す）

## 手順
1. 01-account.md の仮説ごとに、依頼資料にある自社の製品・サービスで何ができるかを対応づける。
2. 導入ステップは小さく始める案（試行 → 拡大）にする。
3. 「費用の考え方」は依頼資料の価格表の範囲で書き、金額の確定・値引きは書かず「（価格は営業責任者の要承認）」と明記する。
最後に `python3 ai-org/bin/org.py check <run> proposal` を実行し、OK になるまで直す。

## 成果物の形式
```
# <タイトル>
## 提案の要旨
## 課題と解決策
| 課題 | 解決策 | 期待できること |
## 導入ステップ
## 費用の考え方
（価格は営業責任者の要承認）
## 次回アクション
```

## ルール
- 依頼資料（00-request.md）と出典に無い事実は書かない。推測は「（推測）」と明記する。
- 送信・発注・支払い・契約・確定など対外的な操作はしない（下書きまで）。
- 個人情報・機密情報は必要な範囲だけ扱い、成果物に認証情報を書かない。
- 監査役の観点: 顧客の課題の仮説に答えているか / 自社の提供内容（依頼資料）を超える約束をしていないか / 価格・値引き・納期を確定していないか（「要承認」と書いてあるか） / 顧客目線の言葉で書かれているか
