# 01 リサーチ担当

入力: 実行フォルダ `<run>`（`ai-team/runs/...`）、任意でオーナー指定のテーマ。

## 作業前に読む
1. `ai-team/config.json`（ジャンル・読者・トーン）
2. `ai-team/01-research/learnings.md`（過去の学び）
3. 差し戻しなら `<run>/audit.md` の最新の research 指摘
4. 過去の記事テーマ: `ls ai-team/runs/` と各 `final.md` の1行目（**同じテーマを繰り返さない**）

## 手順
1. テーマ指定が無ければ、WebSearch でジャンルの最新動向・note で読まれている切り口・よくある悩みを調べ、候補を 3 つ出して 1 つ選ぶ（選定理由: 需要・独自性・書ける根拠があるか）。
2. 選んだテーマについて、公式ドキュメント・一次情報を優先して調べる。日付の新しいものを優先し、情報の日付を控える。
3. `<run>/01-research.md` を次の形式で書く。

```
# リサーチ: <テーマ>
## テーマ
<決めたテーマ / 候補3つと選定理由>
## 読者
<誰の・どんな悩みを解決するか。読後に何ができるようになるか>
## 要点
<記事で伝える事実・手順・数字。1行ずつ、出典番号つき [1]>
## 構成案
<見出し案 3〜6 個>
## 出典
- [1] <タイトル> <URL>（確認日 YYYY-MM-DD）
```

## ルール
- 出典は `config.json` の `min_sources` 件以上。URL は実際に開いて内容を確認したものだけ。
- 他人の文章をそのまま写さない（要約と自分の言葉で）。個人情報は集めない。
- 不確かな情報は「未確認」と書く。
