# /partner — AI相棒の委任ワークフロー

CLAUDE.md の「AI相棒 運用ルール」に従う。ここでは実行手順だけを定める。

## 手順

### 1. 依頼を理解する
- 依頼文から **目的（なぜ）／成果物（何を）／完了条件（どうなれば終わりか）／制約** を抜き出す。
- 足りない情報は、リポジトリ・過去の会話・妥当な既定値で補う。オーナーにしか決められないことだけを、まとめて1回で質問する。
- 依頼を独立したタスクに分解する。

### 2. 振り分ける
各タスクについて CLAUDE.md §3 の表で判断する。
- **このセッションで実行**: そのまま作業して完了させる。
- **新セッションに委任**: 手順 3 へ進む。

### 3. 作業指示書を作って起動する
`docs/partner/brief-template.md` を埋めて、それを `prompt` として渡す。子セッションはこの会話を見られないので、指示書だけで作業が完結するように書く。

`mcp__Claude_Code_Remote__create_session` のパラメータ:
- `title`: `[partner] <タスク名>`
- `prompt`: 埋めた作業指示書
- `permission_mode`: `"auto"`（`"plan"` は使わない）
- `tags`: `["partner"]`
- `source_url`: 対象リポジトリの URL（例: `https://github.com/yminami0210/game-platform`）
- `outcome_branch`: `partner/<短い英語名>`（main に直接 push させない）
- `append_system_prompt`: 次の一文を入れる
  「あなたはオーナーの AI 相棒チームの一員です。リポジトリの CLAUDE.md の停止ラインを厳守し、それ以外は確認なしで自律的に完了まで進めてください。最後に、結論・変更点・確認結果・残課題を日本語で報告してください。」

Claude チャット（コード不要の作業）に回す場合は、`list_environments` で `remote_cowork` 種別の環境を探す。見つかれば、その `environment_id` を指定して起動する。無ければこのセッションで実行する。

### 4. 記録する
`docs/partner/sessions.md` の表に 1 行追加する（日付、session_id、タイトル、目的、状態）。

### 5. 追跡して仕上げる
- すぐに結果が必要なら、`send_later` で 10〜30 分後に自分宛ての確認を予約する。そのあと `get_session` で `status_bucket` を確認する。
- `failed` や停滞のとき: 原因を読み、追加の指示を送るか、このセッションで引き取る。
- 完了したとき: 成果物（ブランチ・PR・差分）を確認し、問題がなければ `sessions.md` を「完了」に更新して、そのセッションをアーカイブする。

### 6. オーナーに報告する
結論 → 起動したセッション一覧（タイトル・目的・状態）→ 確認結果 → 残課題、の順で短く報告する。
