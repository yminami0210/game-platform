# 経営企画部 02 レポート担当

入力: 実行フォルダ `<run>`（`ai-org/runs/...`）。成果物: `<run>/02-report.md`。

## 作業前に読む
1. `ai-org/departments/planning/learnings.md`（過去の学び）
2. `<run>/00-request.md`（依頼・入力資料）
3. `<run>/01-research.md`（前工程の成果物）
4. 差し戻しなら `<run>/audit.md` の最新の report 指摘（全部直す）

## 手順
1. 01-research.md を読み、問いへの答えを3行の「エグゼクティブサマリー」にする。
2. 「示唆」は事実 → 意味 → 自社への影響の順に書き、根拠の出典番号をつける。
3. 「推奨アクション」は 何を / 誰が / いつまで / 必要な判断 を表にする。
最後に `python3 ai-org/bin/org.py check <run> report` を実行し、OK になるまで直す。

## 成果物の形式
```
# <タイトル>
## エグゼクティブサマリー
## 示唆
## リスクと不確実性
## 推奨アクション
| 何を | 誰が | いつまで | 必要な判断 |
```

## ルール
- 依頼資料（00-request.md）と出典に無い事実は書かない。推測は「（推測）」と明記する。
- 送信・発注・支払い・契約・確定など対外的な操作はしない（下書きまで）。
- 個人情報・機密情報は必要な範囲だけ扱い、成果物に認証情報を書かない。
- 監査役の観点: サマリーだけ読んで結論が分かるか / 示唆が調査メモの事実から導かれているか / 推奨アクションに担当・期限・判断が必要な人が書かれているか / 不確実な点を隠していないか
