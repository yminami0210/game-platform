## 判定の理由
デザインは合格ライン（8）に届き、権利・完成度もほぼ問題ない。止める理由は1つで、**難易度が約130秒で頭打ちになり、狙いのうまい人は5〜10分続く**こと（canvas の「1〜3分」、learnings 002）。開発担当の申告の最大238.5秒はボットが弱いためで、上限が無いことを隠している。

## 開発担当への指摘（そのまま直せる形）
1. **（必須）130秒より後も厳しくし続け、終わりが必ず来るようにする。** `SIM.diff(t)` の上限を外すか、120秒以降に2段目を足す。例:
   - 網の幅: 120秒以降もさらに縮める（`netW` の下限 58 → 40、`- Math.max(0, t - 120) * 0.25` を足す）。ど真ん中の幅は網の17%なので、下限40で ±6.8
   - 象の速さ: 上限 112 → 150（`30 + t*0.62` を 197秒まで伸ばす）
   - 砂袋: 120秒以降は4つ（`t < 120 ? 3 : 4`）。綱渡りの速さの上限 84 を外す
   - 退屈の目盛り: 120秒以降は 5秒 → 4秒（`K.TICK` を時間で短く）にして「ずっと待ってど真ん中だけ狙う」も効かなくする
   - 目安: **狙いがぴったりで最大3.5秒待つボット（状態を複製して全部の角度×火薬を試す強いボット）で、終了時間の中央値150〜180秒・最長240秒以下**。人を想定したボット（0.35秒・±3°・火薬±4%）で中央値70〜120秒・最長180秒前後。両方の数字を design.md か plan.md に書いてから再監査に回す（弱いボットだけで測らない）
2. **（必須）結果画面の天幕の絵で煤の跡が読めるようにする。** `endGame` で刷る天幕の絵は、煤の跡を濃く（`drawSoot` の不透明度 0.55 → 0.85 程度、または結果用に墨の芯を太く）し、天幕の絵全体のコントラストを少し上げる（今は帆布の明るい面が白っぽく飛んで見える）。撃った回数ぶん増えた跡が一目で数えられること（印象に残す1点）
3. （推奨）横画面の引っぱりを縦と同じ手応えにする。`updatePull` の `PULL0`・`PULL_OK` を世界座標でなく表示ピクセルで決める（例: `L = Math.hypot(...)` を `/ s` せず CSS px で測り、PULL_OK = 110px 前後）。当たり判定の火の輪の大きさの差は自動プレイで有利不利が出ていないので、そのままでよい
4. （推奨）デザインの小さなずれを直す: 曲芸師の腰帯の山吹 → 日なた色か深緑／投げ上げる帽子の帯と「ドン」の影版の牡丹 → 墨か帆布の影／砂袋の `base + amp` を袋の下端が客席（y=396）より上に収まるよう、`amp` の上限を `396 - 20 - base` で切る
5. （推奨）象と大砲の輪郭を、`inked` の太さ一定の stroke から、`brushPts` で入り抜きのある筆の面に替える（少なくとも象の背と鼻、大砲の筒の上側）。象の通り道の帯は四角の P() をやめ、短い擦れの重なりだけ（または縁を波打たせた形）にする
