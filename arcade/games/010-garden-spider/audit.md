## 0. Fit
- plan.md の Why は、キャンバスのペイン「覚えることが多い・仕事を思い出す」に「庭の蜘蛛が網を張る」という仕事と無縁の題材で答え、ゲイン「1回で気持ちいい瞬間がある」に「張った糸に虫が飛び込み、ぷるんとしなる瞬間」で答えている。会社の Core（すき間時間に1〜3分没頭）とも合う。
- 気になる点: 覚える決まりが多い（ハエ・ガ・カナブン（結び目が要る）・テントウムシ −3・ミツバチは糸を切る・スズメバチ・風）。タイトル画面では2行だけ見せ、ほかは初めて出たときに一度だけ札で教える作りなので、ペイン「覚えることが多い」に逆らうほどではない。
- **合格**

## 1. 楽しさ
- 判断して避ける要素: スズメバチの道（黄と黒の撚り糸）にかかる糸は、留めがレモン色に変わる。予告は正確で、予告の付いていない糸が破られたことは一度も無かった（ランダムに張るボットで 300 回・スズメバチ 1159 匹・破られた糸 867 本、すべて予告の付いた糸）。一度も切らない雑なボットは 81〜91% が途中で失敗（中央値 68〜83 秒）し、切るボットは 0〜2% まで下がる（下の直した場合）。判断は効いていて、失敗（網が破れる・やぶれ ●●●）もはっきり分かる。
- 30秒で分かるか: 「まち針を2つ押すと糸が渡る」は数秒で分かる。最初のハエがかかって「びよん」としなり、露のビーズがはじける所が気持ちいい瞬間として働いている。
- fps: 縦 57.4／横 58.3／小型 58.8（dpr 2）。
- 終了時間: 上手なボットはみな 120 秒（日暮れ）で終わる。点数がいちばん伸びる 20 秒は、終わりの位置の中央値で 97〜112 秒（終盤）。最後の 20 秒は全体の約 3 割を稼ぐ。

### ① 固定長でも、上手い人と普通の人の差・もう一回の動機はあるか
- 点数のばらつきは大きい（同じボットでも p10 約 45／中央値 約 95／p90 約 200）。同じ乱数の種で戦い方を変えても点数の相関は 0.13 しかなく、差は種ではなく網の育て方と守り方から出ている。固定長なのは「ひと日」の見立てとして合っていて、差は「何点まで行けたか」と「網を破られずに夕方を迎えられたか」ではっきり出る。結果画面の「ハエ○匹 ガ○匹 カナブン○匹」と自己ベストで、もう一回遊ぶ理由もある。
- ただし、結び目を狙って張るボットが、空いている所に雑に張るボットより点が低かった（中央値 83〜104 対 133）。「結び目を作って網目を細かくする」腕の見せ所が、まだ点数に効いていない（カナブンは平均 2.8 匹）。→ 改善案 3。

### ② 人想定ボットの 14% の失敗は「納得の失敗」か → **大半が理不尽**
- 自分の人想定ボット（反応 0.35 秒、タップのぶれ ±6px、押しっぱなし 0.5〜0.9 秒）でも、縦で **13%** が途中で網を落とした（開発担当の 14% と一致）。
- 原因は予告の読み落としではなく、入力の判定にある。`pointerdown` が **まち針・結び目（26px 以内）を糸より先に拾う** ので、次の糸は長押しで切れない。
  - 長さ 52px 未満の短い糸（両端のまち針が 26px の円で全部を覆う）
  - 結び目の多い糸（結び目のまわり 26px がすべて「結び目を選ぶ」に化ける）
  - 横画面では `26 / Lay.s`（s ≈ 0.67）で約 39 ワールド px になり、範囲がさらに広い
- 測った数: 予告が出た回のうち、**長押しできない糸がまじる回は縦で 37%（予告の付いた糸の 13〜14%）、横で 27% の糸**。そのような糸を正しく長押ししても、まち針や結び目が選ばれるだけで糸は切れず、時間切れで破られる。
- 入力の優先を「長押し中は糸」に変えただけのボット（ほかは同じ）では、**失敗が 13% → 2%（縦）、28% → 1%（横・タッチ）**、上手なボットは 14% → 0% になった。残る失敗の大半は、正しい操作が受け付けられないことから来ている。
- さらに、まち針を選んだまま糸の結び目の近くを長押しすると、`sel >= 0 && sel !== a` の分岐で **そこへ新しい糸が張られる**。スズメバチの道に糸を足してしまうことがあり、罰が増える方向の誤作動になる。
- 押しっぱなしの長さを 0.3〜0.8 秒に振ると、0.5 秒に届かず離した回は何も起きない（真ん中からほどける表示は出るが、離すと途中の進みは消える）。人想定ボットの失敗は 40% まで上がった。表示がある分ボットよりは気付けるが、急いでいる場面で「切ったつもり」になりやすい。→ 指摘 2。

### ③ 蜘蛛・ハチが苦手な人にも気持ち悪くないか → **問題無し**
- 蜘蛛は丸い腹に白い結び玉の十字、膝の無い短く太い麻色の脚で、ワッペンに見える。目・毛・牙は無く、画面の約 3% と小さい。寄りの演出も無い（`drawPlay` は小さいまま糸の上を動くだけ）。
- スズメバチは針・顎が無く、羽は線だけ。ミツバチは丸い胴が1つで、粒の群れ（集合体）にならない。捕まえた虫は銀の繭にくるまれて消えるだけで、食べる場面は無い。露のビーズは 30px に1粒以下で、房にならない。
- 失敗の演出は「糸が切れて丸まる」「やぶれ」の札と画面のわずかな揺れ（揺れを減らす設定では揺れない）だけで、刺激は弱い。

- **楽しさスコア: 6/10**（判断の芯と気持ちいい瞬間はある。ただし、正しい長押しが受け付けられずに網が破られる理不尽が約 1 割の回で終わり方を決めている）

## REVISE の指摘（開発担当がそのまま直せるもの）
1. **長押しで糸を切るとき、まち針・結び目より糸を優先する。**（必須）
   - `pointerdown` では、近くに糸がある（`G.pickThread(wx, wy, 16 / Lay.s) >= 0`）とき、まち針・結び目の選択・連結をすぐには行わない。`press = { tid, t0, x, y, a }` として、まち針の候補 `a` も持っておく。
   - 0.5 秒（指摘2で短くする場合はその長さ）押し続けたら糸を切り、`a` の選択も連結もしない。
   - その前に離したら、ふつうのタップとして `a` の選択・連結を行う。行う場所は `up()`。動いた距離が 12px を超えた場合はドラッグとして今のまま扱う。
   - 糸が2本以上近いときは、スズメバチの予告が付いた糸（`threatSet(G)`）を先に選ぶ。
   - 右クリック・キーボードの X は今のままでよい。
2. **押しっぱなしの長さに余裕を持たせる。** 切れるまでの長さを 0.5 秒 → 0.35 秒に縮めるか、途中で離しても 0.4 秒ほどは進みを残し、もう一度押せば続きから切れるようにする。進み（真ん中からほどける線）は今の見せ方のままでよい。
3. 横画面の左下の案内札は、`wrap()` に任せず、語の切れ目で行を分けた文にする。例: `["黄と黒の撚り糸は", "スズメバチの通り道", "かかる糸は長押し（右クリック）で切る"]`。fallback フォントでも語の途中で折れないことを、844x390 の撮影で確かめる。
4. **直した後の確かめ方**（各 200 回以上。`index.html` の logic と入力の判定をそのまま使う）
   - 人想定ボット: 反応 0.35 秒、タップのぶれ ±6px と ±12px、押しっぱなし 0.3〜0.8 秒。縦（s = 1）と横（s ≈ 0.67）で、途中失敗が **5% 以下** になること。予告の付いた糸を正しく長押しして切れなかった回数が **0** になること（短い糸・結び目の多い糸を含む）。
   - 長押しのつもりで新しい糸が張られた回数が 0 になること。
   - 一度も切らない雑なボットは、今のまま 80% 以上が途中で失敗すること（判断の要素を弱めない）。

## 改善案（直すと良いもの）
1. 予告の付いた糸を切ると、その糸の結び目につながる糸まで連鎖して切れる（`G.cut` の結び目の連鎖）。正しい対処でも網が大きく減るので、切る前に連鎖して消える糸を薄く示す（長押し中に、消える糸の留めを濃灰の×にする等）と納得感が増す。
2. ミツバチが糸を切るときも結び目の連鎖が起きる。ミツバチは避けようが少ないので、ミツバチに切られる糸は1本だけにする（`G.cut(b.th, "bee")` で連鎖しない）ことを検討する。
3. 腕の見せ所を点数に効かせる。結び目のある糸で捕まえたガ・カナブンに +1 を足す、または夕方のカナブンの割合を上げるなどして、「結び目を作って網目を細かくする」戦い方が、空いている所に雑に張るより稼げるようにする。ボットで、結び目重視の戦い方が雑な戦い方より中央値で上回ることを確かめる。
4. 結果画面: 網が残っていないときも、支柱とまち針を淡い返し縫いの輪郭で残す。または「破られた糸」を切れ端として描き、上半分が空っぽに見えないようにする。理由の行（例: 「スズメバチに 2 回破られた」）を1行足すと、もう一回の動機になる。
5. 奥の大きな生垣の株は、針の向きのばらつきを増やし、扇の放射をやめて、株ごとに2〜3方向の面に割る（草ブラシ感を減らす）。
