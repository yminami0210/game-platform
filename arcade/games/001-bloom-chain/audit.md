## 1. 楽しさ
- **30秒で分かるか: ○** タイトルに「1ラウンド1回だけタップ。花が種を巻き込み連鎖！」、プレイ中は下に「どこか1か所をタップして花を咲かせよう」、HUD に「咲いた n / 目標 m」。やることが1つしかないので迷わない。
- **気持ちいい瞬間: ○** 連鎖の段が深くなるたびにペンタトニックで音が上がるベル音、10/25/40 個で画面フラッシュと「×N BLOOM!」、連鎖が終わると全部の花の位置がきらっと光る締め、全部咲かせると ALL BLOOM（2倍＋花びらが降る）。plan.md の演出は全部入っている。同時発音数を8に絞っているので音割れもしにくい。
- **もう一回遊びたくなるか: ○** BEST を localStorage に保存（try/catch あり）、深い段ほど1輪の点が上がるスコア、おかわり1回、ALL BLOOM の2倍。終了画面ですぐ「もう一回」が押せる。
- 気になる点（軽微）: 花の半径が画面の面積に比例するうえ、種の密度が高いので、序盤は「どこに置いても届く」になりやすく、置き場所を考える手応えは薄め。後半のラウンドの目標（38/56、45/60）で差が出るので、遊びとしては成り立っている。

## 2. 完成度
- **タイトル → 遊ぶ → 結果 → もう一回: ○** title → aim → chain → result →（次ラウンド／おかわり／終了）→ over → タップで startGame。結果画面では1秒待ってからでないと進めないので、誤タップで飛ばすこともない。
- **スマホ操作: ○** pointerdown で即反応、`touch-action:none`、長押しメニューも止めている。右上のミュートは 54px 四方で押しやすい。PC は矢印/WASD＋Space/Enter、M でミュート。
- **はみ出し: ○（縦画面）** 100dvh のキャンバスに DPR 対応、縦の 390×844 ではすべて画面内に収まる。
- 軽微な指摘: 文字の倍率が `S = min(W/390, H/700, 1.6)` なので、スマホを横にしたとき（例 844×390 で S≈0.56）はタイトルの説明文が約7px、HUD が約8pxまで小さくなり読みにくい。はみ出しはしない。次に直すときは、文字サイズだけ `Math.max(0.8, S)` のように下限を付けるとよい。

## 3. 権利・安全
- **実在作品との類似: 問題なし** 名前・見た目は、オリジナルの図形（円＋6枚の花びら、光の点）と配色だけ。「タップで連鎖反応」はジャンルとしてよくある仕組みで、特定の作品のキャラクター・ロゴ・名前・見た目は使っていない。
- **暴力・性的表現: なし** 花が咲くだけの穏やかな内容。フラッシュは白で不透明度25%以下・0.3秒ほどなので刺激は弱い。
- **外部通信: なし** fetch / XHR / WebSocket / 外部の src・link・http 参照はどれもない。音は Web Audio で生成、フォントもシステムフォント。保存は localStorage のベストスコアだけ。
