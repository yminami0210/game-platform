## ブロッカー

### B1. 旧版（5人60分）の保存データで記録帳「人物」タブが落ちる
- 該当: app.js:63-72（`Object.assign(S.save, store.load(KEY))`、検証なし）と app.js:436-438（`rooms[r].tone`）。
- 原因: シナリオ id が旧版と同じ `shiomi-hotel`、保存キーも同じ `immersive-hour:v1:shiomi-hotel`。旧版の `witnessed` には廃止した部屋 `kitchen` の ID が入る（旧版の部屋は clock/room207/office/bar/lobby/kitchen、現行は kitchen なし）。`rooms['kitchen']` が undefined のため `r ? rooms[r].tone` が TypeError を投げる。
- 再現（スクリプト）: 「人物」タブを開く前に localStorage へ次を入れてリロードする。
  `localStorage['immersive-hour:v1:shiomi-hotel']=JSON.stringify({loops:3,seen:{X9:true},truths:{T_chiyo:true,T_final:true},witnessed:{chiyo:{0:'kitchen',1:'lobby',45:'bar'}},notes:''})`
  → 記録帳 → 人物 で例外、タブが空になる。
- 副作用（落ちはしない）: ヘッダー「手がかり 2/8」は `Object.keys(S.save.truths).length`（app.js:318）で、旧 ID も数えるため実数より増える。人物タブの `known/20分` は 20 分以降のキーも数えるため「45/20分」になりうる。`T_final` 等は現行にない ID。
- 修正案（担当: coder）: 読み込み時に `seen/truths` を現行シナリオの scene/truth ID でフィルタし、`witnessed` は `m < SC.length` かつ `rooms[r]` が存在するものだけ残す。`Object.keys(truths)` を `SC.truths.filter(t => S.save.truths[t.id]).length` に変える。または保存キーを `v2` に上げる（旧データを捨てる）。
- 確認方法: e2e に上の保存データを先に注入するケースを 1 件足し、人物タブを開いてコンソールエラーなし・ヘッダーが x/8 以内であることを見る。

## 直したほうがいい点（通すが修正推奨）
1. 場面の「？」ボタンと見た場面ボタン（`.sc-btn` min-height 30px）、「追う」ボタン（`.follow` min-height 32px）が brief の 44px 未満。記録帳の表は 5 列で幅が狭く、「？」は押しやすいが場面名ボタンは小さめ。目標 44px、難しければ行の高さだけでも確保。
2. `prefers-reduced-motion` の指定が 1 件だけ（style.css）。`murmur` の点滅や toast の移動が対象に入っているか確認。
3. 「記録帳の『？』を見る」ボタンは終演シートの 3 つ目で、幅が内容サイズのため主ボタンと揃っていない。細かい点だが導線としては小さい。`記録帳を開く` と役割が近いので、手がかりが新しく開いた周だけ「？」側を出す、などで 1 つにまとめてもよい。
4. 追跡で部屋が変わるとき toast（`〜を追って〜へ`）が出るようになったが、`aria-live="polite"` の toasts 領域に入るのでスクリーンリーダーには読まれる。一方、地図上の「あなた」の移動は視覚のみ。大きな穴ではない。
5. K_song のヒント「時計塔とバーは、床一枚でつながっている」は、手がかりが開く前に見える。上と下の歌の仕掛けを少し先に言っているので、周 2 の発見の驚きを守るなら、別の言い回しを検討。

## プレイテスト指摘の解消確認（全て解消）
- 終演画面の null: `showSheet` と `el()` が null/false を除外（app.js:20、336）。e2e で `"null"` が出ないことを確認する assert あり。
- 移動の判断材料: 隣室に人がいれば灰色の点（`.presence`）、場面中なら「…話し声」。環境場面（A1 など人物なしの場面）では「…話し声」が出ない assert あり（e2e 周6）。
- 上と下の歌: K_song は T2 と M2 の両方（上と下の両側）を見て初めて開く。文面は「同じ節が、どこかで重なった。」で新規性を説明しない。
- 「？」の導線: 終演シートに「記録帳の『？』を見る」、記録帳に凡例、「？」を押すと「まだ見ていない。次の周、この時刻にここへ。」。
- 複数の手がかりが同時に開く場合: 先頭だけ展開し、残りは `<details>` で折りたたみ。
- ヘッダー時計: 終演後 00:00（`clockText` の `Math.min` を除去）。
- 追跡で視点が変わる: toast で予告。

## brief 方針の確認（問題なし）
- 外部送信・外部画像: `fetch` は同一オリジンの `scenarios/*.json` のみ。`http` は SVG 名前空間 URL のみ。画像参照なし。
- 説明台詞: 04-finale-rumor と 05-book-scenes のスクショを見た範囲では、ト書きは映像的で台詞は短く、説明的でない。終演の噂文も察させる書き方。
