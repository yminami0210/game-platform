## 式（論理座標 幅9×高さ16、距離単位=論理座標1）
- 群れ半径 r(N) = 0.25 + 0.17·√N （N=5:0.63 / 20:1.01 / 40:1.33）。幅=2r。群れはリーダー周りの円内に一様に散らばる。
- 倍率 m(N) = 1 + 0.1·(N−1) （N=5:1.4 / 20:2.9 / 40:4.9）。得点 += 速度·dt·m(N)（毎フレーム積分）。
- 視界半径 R(N) = 2.2 + 0.55·√N （N=5:3.4 / 20:4.7 / 40:5.7）。R より先の岩・罠・ホタルは暗闇で見えない。
- 隙間の通過: 隙間の外に出ている円の面積割合 × N を四捨五入した数が散る（端から失う）。全員通すには 2r ≤ 隙間幅。
- 速度（層1→5）: 3.0, 3.4, 3.8, 4.2, 4.6 u/s。
- 隙間幅（層1→5）: 2.3, 2.0, 1.7, 1.5, 1.3（±0.3 のばらつき）。N=10 で幅1.6、N=20 で2.0 なので「層3以降は10匹前後が全員通せる限界」＝欲張りのジレンマが生きる。
- 壁の間隔: 9（層5は9、±15%）。層の長さ: 80。拾い: 壁の中間に0.9の確率で +1〜3。
- 罠: クモの巣=触れたら2匹捕獲（層2〜）、風=横押し1.2〜1.8 u/s・長さ4（層3〜）、カエル=舌で当たった範囲の20%を払う（層4〜）。
- リーダー移動速度 5.0 u/s（隙間の端から端まで約0.8秒）。

## 初期値の表
値は `balance-proposal.json` を正とする。調整範囲: r0 0.2〜0.35 / rK 0.12〜0.22 / mSlope 0.06〜0.15 / light.base 1.8〜2.8 / light.k 0.4〜0.7 / 隙間 ±0.4 / 速度 ±15% / pickup.prob 0.7〜1.0。

## 腕と運
- 運: 隙間の位置・拾いの出現位置と数・罠の出現。ただし隙間の中心は常に外れ幅が限られ、毎ランの難度差は小さい。
- 腕: 拾う/見送るの選択、隙間への合わせ。概算で上達者の中央値が初心者の約9倍。ボットの差が実人間より大きいので、実測では 2〜4倍 程度に収まる想定（仮説2は1.5倍以上）。

## 最初の小さな達成
**100点**（`firstGoalScore`）。初心者ボットの約6割が到達（概算 0.61、基準は5割以上）。約20秒生き延びて群れを少し育てれば届く。20点は100%、150点は45%。

## 調整の手順
1. 実装後、`simulate.mjs` を sticky（初心者）/ lookahead（上達者）で5000回。秒数・スコア比・到達率を上の表と比べる。
2. 初心者が短すぎ: 層1の隙間幅+0.2、または視界 base +0.3。長すぎ: 層1の速度+10%。
3. 上達者が150秒超: 層5以降に距離あたり速度+1%の上昇（上限なし）を足す。短すぎ: 層3〜5の隙間+0.1。
4. 100点の到達率が5割未満: firstGoalScore を下げる（到達率5〜7割に）。
5. 1度に1パラメータだけ変更し、下の検証ログに日付・変更・結果を残す。
