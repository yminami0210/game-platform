# 垂直スライス プレイテスト（slice-01）

- 実施: 2026-11-22 / ヘッドレス Chrome（システム導入版）、390×844 タッチ有効、DPR2。360×640 も確認。
- 方法: `game/` をローカルサーバーで起動し、DOM の `data-act` ボタンを実際にタップして遊んだ（方策は戦略ごとに固定。ボットの自動方策は使っていない）。
- 生データ: `studio/playtests/slice-01-raw.json`、スクショ: `studio/playtests/slice-01-shots/`
- 注意: Playwright 同梱の Chromium は CDN が遮断されて入らなかったため、`/usr/bin/google-chrome` を使用。

## 判定

- スライス基準（quality-gates.md）: 自動ゲートで PASS 済み。本テストで追加に見つかった不具合は下記。
- 面白さの核（孫子の原則で配置し、ダイジェストと解説で理由を読む）: **部分的に届いている**。
  - 届いている: 配置→ダイジェスト→解説の流れは一周する。解説は「どこが空いていたか」を指す。即リトライが効く。
  - 届いていない: 原則の選択と斥候報告の信頼度が、勝敗に効いたと体感できる場面を今回の8戦では作れなかった（仮説2・3）。

## 仮説の判定

1. **ダイジェストと解説で「なぜ」が分かるか: 部分的**
   - 良い: 解説は原因を指す。例「山地に敵がいたのに、味方がいなかった。空いた場所から本陣が削られた。」
   - 弱い: ダイジェスト中の字幕は「平地で衝突」「戦は終わった」など短い。戦闘中に「なぜ」は読めない。解説まで行かないと原因が出ない。
   - 弱い: 原則が効かなかった行は「条件が揃わず働かなかった」の定型で、どの条件が揃わなかったかを言わない。
   - 「もう一戦」: 惜(1)が多く、「あと一歩」「あと一歩で勝ちに届く」の文言は届く。
2. **原則の選択が勝敗に効いたと体感できるか: 未確認（今回は届かず）**
   - 効いた時の解説は具体的（例: 谷の敵は退路を断たれ…／間者の報せで敵の居場所が確かになり…）。
   - ただし 8戦（同じ原則組で 2〜4戦）では勝敗の差を読み取れない。原則を変えて 4戦目が勝ったのは1回きりで、再現しなかった。
3. **斥候報告の信頼度を読むことが腕として効くか: 届いていない（今回の8戦）**
   - 信頼度は「確/概/疑」の印と「出所の信頼度: 高/中/低」で示され、読みやすい。
   - しかし信頼度「高」の報告だけを信じた戦略（6）も負けた。報告の正誤は結果画面の理由からしか分からず、信頼度と的中の関係は今回の8戦では検証できなかった。

## バグ一覧（重要度順）

**B1【高】同じ地形に2つ目の兵科を置くと、配置されずに駒を拾ってしまう**
- 再現: 軍議で 歩 を平地に置く → 弓 を選ぶ → 平地の中央（歩の駒の上）をタップ → 弓は置かれず、歩が選択状態になる。
- 平地の左上の余白をタップすると、弓は正しく配置される（確認済み: 中央で `{"inf":"river"}` のまま、余白で `{"inf":"river","arc":"river"}`）。
- 影響: 地形に駒が重なると、地形をタップしても配置できないように見える。2つ以上の兵科を同じ地形に置く判断が、無反応に見えるので混乱する。
- 担当の推定: 実装（画面の駒の描画と入力。`render/view.js` の駒の配置と、`main.js` のタップ判定）。

**B2【中】勝利なのに解説が「火は味方に返り、自滅した」と言う**
- 再現: 風が西の戦で「火攻は風を読む」と「死地に追い込む」を選ぶ（全体の初回実行で1回発生）。結果は「勝利」。解説に「風は西だった。火は味方の江と平地の部隊に返り、自滅した。」が出る。
- 担当の推定: 解説（`core/explain.js` の理由の出し分けが、勝敗と整合していない）。

**B3【中】軍議の画面で、原則札と兵科トレーが見えない**
- 390×844: 原則札は3枚しか見えず、「火攻」「用間」は下端で切れる（スクロールしないと見えない）。スクショ: `studio/playtests/slice-01-shots/r1-first-normal-1-gunji.png`
- 360×640: 「孫子の原則」と兵科トレーが最初の画面の外。下の案内「兵科を選び、地形をタップして配置」は見えるが、スクロールの手がかりがない。スクショ: `studio/playtests/slice-01-shots/viewport-360x640-gunji.png`
- 担当の推定: UI（レイアウトとスクロール領域。`style.css` と `render/view.js`）。
- 影響: 新要素（孫子の原則）の半分が最初に見えない。新規性の一点の露出が落ちる。

**B4【中】「開戦」が灰色のまま、何が足りないかが出ない**
- 原則2つ・全兵科の配置・用間の対象、のどれが未完了かを画面に出していない。案内文は配置の操作だけを言う。
- 担当の推定: UI文言（`main.js` の案内文の出し分け。`data/text.json`）。

**B5【低】解説の文言が定型で、同じ行が繰り返される**
- 「報告の真偽を見直したい」が、空いた地形の行すべてに付く。「条件が揃わず働かなかった」が不発の原則で毎回出る。
- 担当の推定: 文言（`data/text.json` と `core/explain.js`）。

**B6【低】凡例がない表示**
- 信頼度の印「疑 / 概 / 確」に凡例がない（「確」が高であることは、文字からは分からない）。結果画面の「惜 / 善戦 / 惜敗 / 勝利」と、上の3つの四角（何段目かの意味）にも説明がない。
- 担当の推定: 文言・UI。

**B7【低】音が無い。触覚は Android の振動のみ**
- 配置や選択に音がない。振動は `navigator.vibrate`（iOS Safari では効かない）。手応えは視覚だけになる。
- 担当の推定: 設計（音を入れるか、視覚の手応えで足りるかの判断）。

**B8【参考】ダイジェストが短い**
- 通常速度で約20秒（早送りで約8〜10秒）。balance の再生 30〜60 秒の目安より短い。数値は gate の管轄のため、ここでは報告のみ。

## 確認済みの良い点

- 介入の画面は分かりやすい: 「機が来た。号令を下せ」→ 部隊を選ぶ → 地形へ。「そのまま」で介入しないこともできる。
- 敵は赤のひし形、味方は青の丸、数字つき。色だけに頼らない（基準どおり）。
- タップ領域: 地形 175×112、兵科の駒 48×52、原則札 112×104、ボタン 56 高。いずれも 44px 以上。
- 表示語彙は brief の表記と合う（斥候報告、信頼度、配置、原則、解説、ダイジェストの字幕）。「スキル」「ターン」「クリア」「ステータス」は見当たらなかった。
- 結果画面から「もう一度、軍議を開く」まで1タップ・即時。

## 初めて遊ぶ人として一番気になったこと

「開戦」が灰色のまま理由を言わないこと。原則を何個選べばよいか、どの兵科が置けていないかが分からず、初見の人は止まる（B4 と B3 の組み合わせで悪化する）。

B1（同じ地形へ2つ目の兵科を置くと、駒を拾ってしまい配置されない）。毎回の配置で起きうる、核の操作の無反応。
