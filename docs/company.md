# 会社の方針（2026-10-01 決定）

## 何をする会社か
**AI社員だけで回るインディーゲームスタジオ。** 仕事を忘れて遊べる、純粋に楽しいゲームを作る。
ビジネスの知識はゲームの中身ではなく、**会社の運営**（何が遊ばれているかの分析、次の企画の選定、収益と権利の確認）に使う。

## オーナーとの約束
- オーナーは**ほぼ放置**。判断するのは「外に公開してよいか」と「大きな方向転換」だけ。
- AI社員は作る・試す・直す・記録するまでを自動で行う。公開（外から見える状態にすること）、収益化の契約、お金の受け取りはオーナーが行う。

## 2本立てで並行に進める

**分け方は「作るゲームの規模」で決める**（工程の丁寧さではない）。2026-10-02 にオーナーの指摘を受けて決め直した。

| | ミニゲーム | 大型タイトル |
|---|---|---|
| 1回の遊び | 1〜3分 | クリアまで数時間の冒険（最初のマイルストーンは30分〜1時間） |
| 中身 | 1つの遊び（ルール1つ） | 世界・物語・複数のステージ・ボス・成長と収集。遊びの種類が組み合わさる |
| 構造 | 1画面・1ファイル | ワールドマップ、ステージ、セーブ、進行管理、データで作るステージ |
| 期間 | 1日1本（毎朝） | マイルストーン制で数週間〜数か月 |
| 判定 | 自動QA＋監査 | 区切りごとに自動ゲート＋レビュー、そして**オーナーが遊んで判断** |
| 置き場所 | `arcade/` | `studio/`（企画・判定の記録）と `game/`（本体）。タイトルごとのブランチ |
| 進め方 | `/arcade-make` | `game-studio` の専門エージェント（大型向けに運用を変える。`docs/partner/briefs/title-01.md`） |

### 大型タイトル第1作（2026-10-02 決定）
- 型: **横スクロールアクション**（ワールドとステージ、多彩な仕掛け、ボス、隠し要素）
- 最初のマイルストーン: **ワールド1（最初のダンジョンにあたる1まとまり）を完成品質で**。30分〜1時間遊べる体験版。オーナーが遊んで、広げるか決める
- 以前「大型」として作った「トモシムレ」は規模がミニゲーム相当だったので、大型タイトルから外し、小品として記録だけ残す（ブランチ `studio/flagship` に残す）

ミニゲームで当たった遊び（監査の楽しさスコアが高いもの、実際に遊ばれたもの）は、大型タイトルの仕掛けの種にする。

## 部署の当てはめ
| 部署 | 役割 | 仕組み |
|---|---|---|
| 経営企画 | どの遊びが当たっているかの分析、次の方針 | `/ai-org planning` |
| 開発 | ゲームを作る | `game-studio`、`/arcade-make` |
| 品質保証 | 自動テストプレイ、監査 | `arcade/bin/qa.mjs`、`game-studio` の gate_check・playtester・reviewer |
| 広報 | 開発日記の note 記事、X での告知 | `/ai-team`（公開はオーナー） |
| 法務 | 権利・ライセンスの確認 | `gs-legal`、`/ai-org legal` |
| 経理 | 収益と費用の確認 | `/ai-org finance` |
| 営業 | 第2期まで待機 | `/ai-org sales` |

## 第2期（あとで）
第1期で磨いた制作力を使い、企業研修向けのゲームを有料で受託する（To B）。作品と実績ができてから始める。

## 公開の流れ（オーナーの承認が必要）
1. AI社員が公開候補をまとめる（ミニゲームは `status: ready`、大型タイトルは game-studio の Gate 2 公開承認パック）
2. オーナーが OK を出す
3. main へのマージと GitHub Pages の有効化（初回だけオーナーが Settings で設定）
