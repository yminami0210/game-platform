# ナナシ県 制作体制と判断記録

依頼の「ストーリーマスター1人＋プロダクトマネージャー複数人」は、**役割（責任者の視点）** として置く。
トークン節約が前提なので、役割ごとに別セッションは立てない。1 つのセッションが各責任者の視点で順に判断し、その記録をここに残す。
並列化が本当に必要になったら（例: アバター機能の本実装）、`/partner` で役割単位の子セッションを起動する。

## 役割

| 役割 | 担当範囲 | 判断の軸 |
|---|---|---|
| ストーリーマスター（SM） | 世界観、語彙、出来事テーブル、文体（`server/lore.js`、`world-bible.md`） | 「ないのに、ありそう」か。実在の固有名詞を避けているか |
| PM-ワールド | 町並み、3D 表現、カメラ（`client/town.js`） | 昭和の手触り。軽さ（数百 CP が普通の PC で動く） |
| PM-シミュレーション | CP の行動、県庁の業務、タスクボード（`server/sim.js`） | CP の行動はランダム選択だけ（LLM なし）。ログが「記事の素」になるか |
| PM-メディア | SNS（ナナシッター）、県民新聞、写真（`server/executor.js`、`chronicle.js`） | トークン 0 を既定にする。LLM は上限つきの例外 |
| PM-参加基盤 | 住民課、人間アバター、将来のマルチプレイ | 後で拡張できる形か。安全か（token、入力検証） |

## /findskills の解釈

`/findskills` はこの環境に無いコマンドなので、「責任者の目線で必要なスキルを洗い出し、どれを誰に持たせるか判断する」作業として実施した。結果は次の表。

| スキル | 持たせる先 | 実行方法 | トークン |
|---|---|---|---|
| sns_post（SNS投稿） | 広報課の CP | テンプレート／OmniRoute／Claude Code（`nanashi-koho`） | 既定 0、上限 4 回/日 |
| photo（写真撮影） | 広報課の CP | ブラウザが 3D を撮影（断面キャプチャ） | 0 |
| newspaper（県民新聞） | 広報課長 | テンプレート／OmniRoute／Claude Code | 既定 0、上限 1 回/日 |
| resident_register（転入・アバター登録） | 住民課の CP | API（`nanashi-jumin`） | 0 |
| 部署ルーチン（畜産課の牧場聞き取り 等） | その他の部署 | 決められた選択肢からランダム | 0 |

## 判断記録

1. **[PM-メディア] LLM は既定で使わない。** 町の出来事・SNS・新聞はテンプレートで成立させ、LLM は「文章を少し良くする」だけに使う。上限到達や失敗のときはテンプレートに自動で戻すので、止まらない。
2. **[PM-メディア] LLM に渡すのはローカルで要約したダイジェスト（最大 8 件）だけ。** 生ログは渡さない。同じ入力はキャッシュして、もう一度は課金しない。
3. **[PM-メディア] Claude Code は OmniRoute 経由（`ANTHROPIC_BASE_URL`）で、ツールなし・リポジトリ外の cwd で起動する。** CLAUDE.md やスキルを読み込ませず、入力トークンを最小にする。
4. **[PM-シミュレーション] CP の意思決定は時間帯と役割で重みを変えるランダム選択。** 数百人いても CPU だけで回る。
5. **[PM-シミュレーション] 実タスクはタスクボードで「受付 → 移動中 → 作業中 → 完了」と進み、担当 CP が実際に席や現場まで歩く。** 3D の「作業中」表示とタスクの進み具合が同じデータから出るので、表示と処理がずれない。
6. **[PM-シミュレーション] Claude Code で実行するタスク（external）は、結果が届くまで 95% で待つ。** 4 時間（ゲーム内）待っても届かなければテンプレートで仕上げる。
7. **[PM-ワールド] 外部アセットは使わず、手続き的に生成する。** 著作権の心配がなく、軽い。電柱と電線、瓦屋根、銭湯の煙突、赤いポスト、自販機で昭和らしさを出す。画面全体にセピアとビネットをかける。
8. **[PM-ワールド] 県庁の執務フロアは屋根を付けない。** 働く CP が上から見え、部署札と作業中ランプで連動がわかる。
9. **[SM] 写真には、フィルムカメラ風の日付（オレンジ色）を写し込む。** 「本当に誰かが撮った」感じを出す。
10. **[SM] 固有名詞はすべて架空にする（まるなな、ナナシマート、名無自動車、七星堂…）。** 実在の企業名・商標は出さない。
11. **[PM-参加基盤] 人間アバターは住民課で手続きしてから、ナナシ駅に到着する。** そのアバターを動かせるのは、登録したブラウザの token だけ。本格的なマルチプレイ（認証、見た目のカスタマイズ、チャット）は次の段階で行う。
12. **[PM-参加基盤] スマホでは「この端末だけで動かす」を基本にする。** シミュレーションをブラウザでもそのまま動く形に分けて（`api.js`・`sim.js`・`chronicle-core.js`・`templates.js`）、サーバーなしで GitHub Pages から遊べるようにする。LLM を使わないので、トークンは 0 のまま。PC のサーバーに同じ Wi-Fi からつなぐ方法も残す。
13. **[PM-ワールド] スマホでは下のタブで画面を切り替え、3D を全面に出す。** 縦長の画面では広角にして、解像度と影を落とし、電池と発熱を抑える。
14. **[オーナー判断 2026-10-11] 今の品質では公開しない。** `docs/release/approved-apps.json` は空のままにする。公開できる品質になったら、改めてオーナーに確認する。
15. **[PM-シミュレーション 2026-10-11] 住人を「世帯・住まい・勤め先・毎日の予定」で一人ずつ管理する。** 住まいは部屋数まで、家族は名字を共有する。くわしくは `docs/nanashi/residents.md`
16. **[オーナー方針 2026-10-11] 駅を町の真ん中に置き、ベッドタウンにする。** 働く人の 85% と高校生が電車で県外へ通い、平日の昼は住民の半数以上が町にいない。県外から通ってくる人と、日帰りの来訪者もいる
17. **[PM-参加基盤 2026-10-11] 管理者モード。** 建てる・移す・回す・壊すができる。置けるかどうかはサーバーと画面で同じきまり（`placementError`）を使う。この PC と、自分の端末の町では合言葉なしで使える
18. **[PM-参加基盤 2026-10-11] HTML（Artifact）で見られるようにする。** サーバーなしの「この端末で動かす」版を Artifact に置く（非公開）

19. **[オーナー方針 2026-10-11] 人の見た目は部品の組み合わせ（顔・目・まゆ・口・髪型・髪の色・肌・体型・上着・ズボン・小物）。** 住民台帳に記録し、地図・3D・似顔絵・建物の中・目線で同じ見た目を描く（`server/looks.js`、`client/portrait.js`）。見た目は人ごとの乱数で決め、町の動きの乱数は変えない
20. **[オーナー方針 2026-10-11] 見え方は2つにしぼる。** 全景（つまんで拡大、建物をタップで中の全景）と、人の目線（1人称）。県庁・広報課・商店街・駅のカメラボタンはなくし、県庁の中は建物の中の全景で見る。どちらも WebGL なしで描くので iPhone でも見られる
21. **[オーナー提案 2026-10-11] 店を「利用する」とミニゲームが始まる。** 町の側は入口と約束ごと（`docs/nanashi/minigames.md`）だけを持ち、ゲーム本体は別に作って差し込む。結果は町のログと今日のお客の数に残す（LLM 不使用）
22. **[PM-参加基盤 2026-10-11] 人・店・家をタップすると詳細カード。** 人: 似顔絵・見た目・世帯・住所・勤め先・今日の予定・いま。店: 営業時間・営業中か・いる人・働く人・今日のお客・最近の出来事。家: 住所・世帯・いま家にいるか

23. **[オーナー指摘 2026-10-11] 人形は人らしく、向きを持たせる。** 首・なで肩・腕と手・靴・スカート、白目のある目と鼻。歩く向きで正面・背中・横顔を描き分け、歩くと手足が振れる。建物の中では見ている先（テーブル・カウンター・黒板）で向きを決め、県庁の机は向かい合わせ
24. **[バグ修正 2026-10-11] 電車が行ったり来たりしていた。** 画面に届く時刻が「分」の切り捨てで、画面側の推定が行き過ぎては戻っていた。小数の時刻を送り、画面の時刻は決して戻さずになめらかに進める

25. **[オーナー構想 2026-10-11] 「48個目の都道府県」世界観 IP。** 主役は SNS 上の ARG。3DCG の町は、4つのアカウント（観光課・住人A・住人B・ふじや）の裏側の正本にする。構想書 `docs/product/nanashi/business-plan.md`
26. **[PM-メディア 2026-10-11] 4つのアカウントを町の実在の住人・店に結びつけ、テンプレートで投稿する（トークン 0）。** 投稿の時刻・場所・メニューは町の暮らしと一致させる。過去ログは町を早回しして作る（`tools/nanashi_pastlog.mjs`）。外への投稿はオーナー

27. **[PM-メディア 2026-10-11] 4人の投稿者に名前と設定をつける。** 菜種 澪（住人A）・梨木 さくら（住人B）・藤谷 修（ふじや）・七瀬 光太郎（観光課）。町の住人に配役し、名前・年齢・見た目・家族の名字・暮らしの時刻・行きつけの店をそろえる（`docs/nanashi/personas/characters.md`）。ふじやの定休日（水曜）には誰もふじやの話をしない

28. **[オーナー指摘 2026-10-11] 世界設定の正本は Claude Docs の「ナナシ県 世界観バイブル」。** それまでリポジトリは正本を見ずに作っていた。海を川（ヨコネ川）に、ナナシ線をヨコデン（単線・2両・30分に1本）に、ナナミ市・オトギ町を下川原市・深田市に、ななっしーをナナシくんに、SNS を正本の4アカウントと登場人物に替えた。正本にない設定は `proposals.md` で承認を待つ（決定 25〜27 の住人A・住人B・ふじや・独自の奇習は廃止）

29. **[オーナー判断 2026-10-12] 県庁のアカウントがナナシくんのアカウント。** SNS は「ナナシくん｜ナナシ県庁」「ナナシ放送」「スーパーまるやす」の3つ。県庁のお知らせとナナシくんの出演の一言を同じアカウントから出す

## 次の候補（優先順）

1. ミニゲーム本体（喫茶・銭湯・スーパーから）。できたら `client/minigames.js` に url を入れる
2. 目線の画面で、自分のアバターを歩かせる操作。畜産課の牧場視察など、部署のイベントを現場で演出する
3. 季節と天気（雨・雪）、年中行事（夏祭り・運動会）を出来事テーブルに加える
4. 新聞のアーカイブ閲覧と、写真アルバム
5. 町の「今」をまとめた週報を、Artifact や Notion へ書き出す（オーナーの確認後）
