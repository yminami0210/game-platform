# ナナシ県 制作体制と判断記録

依頼の「ストーリーマスター1人＋プロダクトマネージャー複数人」は、**役割（責任者の視点）** として置く。
トークン節約が前提なので、役割ごとに別セッションは立てない。1 つのセッションが各責任者の視点で順に判断し、その記録をここに残す。
並列化が本当に必要になったら（例: アバター機能の本実装）、`/partner` で役割単位の子セッションを起動する。

## 役割

| 役割 | 担当範囲 | 判断の軸 |
|---|---|---|
| ストーリーマスター（SM） | 世界観、語彙、出来事テーブル、文体（`server/lore.js`、`world-bible.md`） | 「ないのに、ありそう」か。実在の固有名詞を避けているか |
| PM-ワールド | 町並み、3D 表現、カメラ（`client/town.js`） | 昭和の手触り。軽さ（数百 CP が普通の PC で動く） |
| PM-シミュレーション | CP の行動、県庁の業務、タスクボード（`server/sim.js`） | CP の行動はランダム選択だけ（LLM なし）。ログが「記事の素」になるか |
| PM-メディア | SNS（ナナシッター）、県民新聞、写真（`server/executor.js`、`chronicle.js`） | トークン 0 を既定にする。LLM は上限つきの例外 |
| PM-参加基盤 | 住民課、人間アバター、将来のマルチプレイ | 後で拡張できる形か。安全か（token、入力検証） |

## /findskills の解釈

`/findskills` はこの環境に無いコマンドなので、「責任者の目線で必要なスキルを洗い出し、どれを誰に持たせるか判断する」作業として実施した。結果は次の表。

| スキル | 持たせる先 | 実行方法 | トークン |
|---|---|---|---|
| sns_post（SNS投稿） | 広報課の CP | テンプレート／OmniRoute／Claude Code（`nanashi-koho`） | 既定 0、上限 4 回/日 |
| photo（写真撮影） | 広報課の CP | ブラウザが 3D を撮影（断面キャプチャ） | 0 |
| newspaper（県民新聞） | 広報課長 | テンプレート／OmniRoute／Claude Code | 既定 0、上限 1 回/日 |
| resident_register（転入・アバター登録） | 住民課の CP | API（`nanashi-jumin`） | 0 |
| 部署ルーチン（畜産課の牧場聞き取り 等） | その他の部署 | 決められた選択肢からランダム | 0 |

## 判断記録

1. **[PM-メディア] LLM は既定で使わない。** 町の出来事・SNS・新聞はテンプレートで成立させ、LLM は「文章を少し良くする」だけに使う。上限到達や失敗のときはテンプレートに自動で戻すので、止まらない。
2. **[PM-メディア] LLM に渡すのはローカルで要約したダイジェスト（最大 8 件）だけ。** 生ログは渡さない。同じ入力はキャッシュして、もう一度は課金しない。
3. **[PM-メディア] Claude Code は OmniRoute 経由（`ANTHROPIC_BASE_URL`）で、ツールなし・リポジトリ外の cwd で起動する。** CLAUDE.md やスキルを読み込ませず、入力トークンを最小にする。
4. **[PM-シミュレーション] CP の意思決定は時間帯と役割で重みを変えるランダム選択。** 数百人いても CPU だけで回る。
5. **[PM-シミュレーション] 実タスクはタスクボードで「受付 → 移動中 → 作業中 → 完了」と進み、担当 CP が実際に席や現場まで歩く。** 3D の「作業中」表示とタスクの進み具合が同じデータから出るので、表示と処理がずれない。
6. **[PM-シミュレーション] Claude Code で実行するタスク（external）は、結果が届くまで 95% で待つ。** 4 時間（ゲーム内）待っても届かなければテンプレートで仕上げる。
7. **[PM-ワールド] 外部アセットは使わず、手続き的に生成する。** 著作権の心配がなく、軽い。電柱と電線、瓦屋根、銭湯の煙突、赤いポスト、自販機で昭和らしさを出す。画面全体にセピアとビネットをかける。
8. **[PM-ワールド] 県庁の執務フロアは屋根を付けない。** 働く CP が上から見え、部署札と作業中ランプで連動がわかる。
9. **[SM] 写真には、フィルムカメラ風の日付（オレンジ色）を写し込む。** 「本当に誰かが撮った」感じを出す。
10. **[SM] 固有名詞はすべて架空にする（まるなな、ナナシマート、名無自動車、七星堂…）。** 実在の企業名・商標は出さない。
11. **[PM-参加基盤] 人間アバターは住民課で手続きしてから、ナナシ駅に到着する。** そのアバターを動かせるのは、登録したブラウザの token だけ。本格的なマルチプレイ（認証、見た目のカスタマイズ、チャット）は次の段階で行う。

## 次の候補（優先順）

1. アバターの見た目カスタマイズ、WASD で歩く操作、ほかの人のアバターとのすれ違い
2. 県庁の内部（各課の詳細ビュー）。畜産課の牧場視察など、部署のイベントを現場で演出する
3. 季節と天気（雨・雪）、年中行事（夏祭り・運動会）を出来事テーブルに加える
4. 新聞のアーカイブ閲覧と、写真アルバム
5. 町の「今」をまとめた週報を、Artifact や Notion へ書き出す（オーナーの確認後）
