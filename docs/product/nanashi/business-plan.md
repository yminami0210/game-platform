# 「48個目の都道府県」世界観IP ビジネス構想書（概要版）

- 状態: **オーナー提示（2026-10-11）**。Core・Why・ビジネスモデルの正本。PM の補足は末尾の「PM メモ」に分けて書く
- 関連: キャンバス `canvas.md`、リスクと対策 `docs/nanashi/arg-risks.md`、設定集 `docs/nanashi/world-bible.md`、SNS アカウントの設計 `docs/nanashi/personas/`

## マクロ背景
AI に仕事を置き換えられて可処分時間が増える一方で、コンテンツは一部に集中している（寡占化）。
⇒ 単一の IP ではなく、広がりのある「世界観（ルール・箱）」そのものを IP にする。

## 1. コア・コンセプト
- **概要**: 存在しないはずの「48個目の都道府県」を SNS 上に作る。
- **体験価値**
  - 日常にひそむ違和感から始まり、断片的な情報がつながることで認知が揺らぐ（ゲシュタルト崩壊）。
  - 暇な社会人が、知的好奇心と考察で「時間を溶かす」代替現実（ARG）体験。
- **基本スタンス**
  - 種明かしはしない（永遠の日常化・定住化）。
  - プロフィールなどに「仮想・フィクション」と明記し、炎上や誤解を避ける（安全な嘘）。

## 2. 立ち上げ設計（Go-to-Market）
少人数の副業リソースで「コールドスタート（無風状態）」を突破する、ハイブリッド運用モデル。

| 役割 | アカウント | 運用 | 内容 |
|---|---|---|---|
| 点：世界観の土台 | 県庁観光課 | AI 自動運用 | それぞれの視点で日常を投稿し続ける。同じ店・同じ固有名詞に触れて、話が交差する |
| | 住人A（女子高生・日常） | AI 自動運用 | |
| | 住人B（OL・グルメ） | AI 自動運用 | |
| | ローカル料理屋（メニュー） | AI 自動運用 | |
| 線：起爆・着火 | 「決定的な異物」 | 投下 | 例：料理屋の、狂った手書きの「本日のおすすめ」 |
| | 部外者・発見者 | **人間が手動介入** | 「外から」ツッコミ・引用で広げる |
| | 料理屋 | AI | 日常として淡々と真面目に返信する ⇒ シュールさでバズり、考察が始まる |

## 3. マネタイズ設計（世界観と連動した4層構造）
単なる集金ではなく、「課金する行動そのものが世界観への没入になる」導線を作る。

| 手法 | 提供価値（世界観での建て付け） | 実装・リスク対策（副業向け） |
|---|---|---|
| ① 有料コンテンツ | 街に住む小説家の作品、県庁の調査記録 | 純文学で勝負せず、「謎解き・歴史の補完アイテム」として付加価値をつける |
| ② グッズ販売 | 街の名産品、観光記念品 | 在庫・配送リスクをなくすため、オンデマンド印刷（SUZURI・BOOTH など）を使う |
| ③ ふるさと納税 | 架空の自治体への寄附（投げ銭） | 法的な誤解・アカウント停止を避けるため、「ネタ寄附」としてクラウドファンディングなどを使う |
| ④ 移住（サブスク） | 住民票の発行、住民限定 Discord | 運営の労働過多を防ぐため、住民同士が街の文化を広げる UGC 主導のコミュニティにする |

## 4. ネクストステップ（直近の実行項目）
1. **核となる設定集（バイブル）を作る**: 県の名前、特産品、代表的な奇習、料理屋の店名などを最低限決める
2. **AI エージェントのプロンプトを設計する**: 観光課・住人A・料理屋それぞれのペルソナと投稿のトーンを固定する
3. **初期テスト運用を始める**: まず数週間、誰にも気づかれない状態で「街の過去ログ」をためる

## PM メモ（AI相棒。2026-10-11）

### いまのナナシ県（3DCG の町）との関係
構想書の主役は SNS 上の ARG で、3DCG の町はその**裏側の正本**として使う。
- 町では数百人の住人が、決まった暮らしで毎日を過ごしている（住民台帳・電車・店・県庁）。SNS のアカウントは、その中の実在の住人や店に結びつける。住人A が「7時12分の電車」と書けば、町でも本当にその時刻に駅にいる
- だから投稿どうしが自然に交差し、考察する人が後から照らし合わせても矛盾しにくい。「断片がつながる」体験の土台になる
- 過去ログは、町を早回しして作る（テンプレートだけで作るのでトークン 0）。`tools/nanashi_pastlog.mjs`
- 3DCG の町の画面は、④ 移住（住民票・自分の家）と、有料の「県庁の調査記録」の舞台として後から出せる
