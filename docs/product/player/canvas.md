# プロダクトキャンバス: ミニゲームの遊び場（player）

- 状態: Core は会社の Core（確定）に従う／Why 以下は PM 案（オーナー確認待ちの所は questions.md）
- 最終更新: 2026-10-05 / 担当 PM: AI相棒（このセッション）

## Core
- ミッション（会社）: 忙しい毎日から離れて、時間を忘れて没頭できる遊びを届ける
- ビジョン（会社）: 多くの人に愛される作品を生み続ける
- 企業への貢献: 毎日増えるミニゲームを「遊べる場所」にまとめ、遊ぶ人の入口にする（事業戦略2）。将来は「街の住人に話しかけると遊びが始まる」世界にして、ミニゲームの集まりを1つの作品として愛されるものにする

## Why
- ターゲット: 10代〜40代。すき間時間にスマホで、または PC で少し遊びたい人
- ペイン: どこに何があるか分からない／毎回ページを移るのが面倒／終わったら次に何をすればいいか分からない
- ゲイン: 開いたらすぐ一覧、押したらすぐ遊べる、終わったら一覧に戻って次の1本へ。新しい1本が毎日増えている楽しみ
- Fit: ミッション（すぐ没頭できる）に答える

## What
- メンタルモデル: 今は「遊び場の掲示に並んだ札を選ぶ」。将来は「街を歩いて住人に話しかける」
- カスタマージャーニー: 開く → 新しい札が目に入る → 押す → その場で遊ぶ → 戻る → 次の札
- ロードマップ（マイルストーン）:
  1. **M1（今回）**: 一覧 → 押すとその場で遊べる → 戻る。ベストスコアの表示。新着の印
  2. M2: 街の画面（歩ける小さな町並み）。住人ごとにミニゲームを割り当て、話しかけると遊びが始まる
  3. M3: 住人との会話・遊んだ記録・街が少しずつ賑わう仕掛け
- 指標: 1回の訪問で遊んだ本数、もう一回率、2日目にまた来た率（公開後）
- コスト構造: 一度作れば日々のコストはほぼ無い（ミニゲームの追加は日々のバッチ側）
- 収益モデル: 当面なし

## How
- UI: `player/index.html`（一覧と遊ぶ画面を1ページで切り替え）。デザインは game-art-direction §0 に沿ってコンセプトを先に固める（合格ライン 8/10）
- 設計と実装:
  - **日々のバッチ（/arcade-make）とは別物**。player/ はバッチが触らない。バッチの成果物 `arcade/catalog.json` を読むだけ
  - 「ゲームを始める」処理を `player/js/launcher.js` に分け、一覧からも、将来の街（住人）からも同じ関数で呼ぶ
  - ゲームと住人の割り当ては、将来 `player/data/residents.json` のようなデータで持つ（コードに埋めない）
- Go To Market: 公開はオーナー承認後（GitHub Pages）
